# Waypoint — Visual Redesign Addendum v1

> 本章节覆盖原设计文档中与首页视觉、页面排版、Card 风格、项目详情展示方式相关的视觉要求。
> 不修改现有路由、数据结构、SEO、测试体系和核心内容，只重新设计视觉表达与阅读体验。

---

# 1. 本轮重设计目标

当前版本的问题不是功能，而是视觉与信息呈现：

- 首页像标准 AI SaaS Landing Page
- Hero 过大、口号过重
- 页面大量使用深蓝 Card，视觉节奏单一
- 内容虽然完整，但像“把设计文档直接渲染成网页”
- 授信项目详情存在严重文字墙
- Evolution 8 个阶段全部以大 Card 展示，可读性差
- 所有内容的重要程度看起来接近，缺少视觉主次
- 技术标签、状态 Badge、边框使用过多
- 缺少图片、截图、架构图等视觉证据
- 整体缺少“个人站”的安静、克制和编辑感

本次目标不是：

「让网站更炫」

而是：

「让网站更像一个认真记录个人实践、思考和成长的数字空间。」

核心视觉关键词：

Editorial
Personal
Quiet
Precise
Readable
Research-oriented
Human

避免：

AI SaaS
Dashboard
Cyberpunk
Developer Template
大量 Card
大量 Badge
Glow
Gradient
科技蓝铺满页面

# 2. 整体 Art Direction

## 2.1 从深色 AI 网站改为浅色 Editorial 风格

V1 本轮优先尝试 LIGHT THEME。

页面主背景：

#F7F7F4

或接近暖灰 / 米白的 neutral background。

正文主色：

#171717

Secondary Text：

#666660

Border：

#DDDCD6

Accent：

使用一个克制的蓝色，例如：

#2563EB

但 Accent 只能用于：

- Link
- Active State
- 小型 Label
- Hover
- 少量结构提示

禁止大面积蓝色背景。

不要使用大面积深海军蓝。

## 页面留白

不要试图把大量内容塞在一屏。

Section 之间：

Desktop 至少 96–140px

20–28px

不要通过大量 Card 来区分 Section。

优先使用：

Whitespace
Typography
Thin Divider
Alignment

来创造层级。

# 20. Key Design Decisions

不要正文段落堆叠。

做成四个 Editorial Blocks：

01

Workflow vs Agent

确定性任务优先 Workflow；
需要开放搜索和判断时，
才引入有边界的 Agent.


02

LLM vs Code

Code calculates.
LLM interprets.


03

Generate vs Verify

生成与验证是两个不同能力。


04

Modular vs Monolithic

Small capability.
Clear contract.
Independent evaluation.

---

四个块可以：

2 × 2 Grid

但不要完整 Card。

使用：

Top Border
Number
Large Principle
Short Explanation

即可。

# 22. Things That Didn't Work

这是项目的重要内容。

不要隐藏。

但不要像当前文档式 Bullet List。

或中文：

哪些东西没有工作

01

网页做出来了，
报告没有。

原因：
没有最小单元测试和明确验收。

改变：
停止堆功能，重新设计开发方法。


02

模块单独看起来完成，
组合后却不断失败。

...


视觉要求：

Large Failure Statement

↓

Small Reason

↓

Small Change

不要 Card 海。

# 27. Card Rules

本轮必须大幅减少 Card。

原则：

If everything is a card,
nothing has hierarchy.

只有以下场景可以使用完整 Card：

- 真正独立的交互组件
- 有明确容器需求的视觉内容
- 特定 Highlight

普通：

Project
Thought
Resource
Evolution Stage

默认禁止使用大圆角 Card。

rounded-xl everywhere

# 30. Tags

当前 Tag 数量过多。

原则：

最多展示 3 个主要 Tag。

其他 Tag 放详情页末尾或者不显示。

Tag 不需要每一个都有边框。

可以简单显示：

RAG · Evaluation · Financial AI

而不是：

[RAG] [Evaluation] [Financial AI]

# 31. 图文比例

目标不是精确比例，但视觉上避免连续出现：

超过 2–3 屏纯文字。

原则：

2–3 个文字 Section 后，
必须出现：

截图
图表
架构图

可视化关系
或大号 Key Statement

打断阅读。

# 38. 最重要原则

Waypoint 不应该试图证明：

「这是一个很厉害的 AI 网站。」

Waypoint 应该让访问者自然感觉到：

「这里有一个人在认真做东西，
认真想问题，
也认真记录自己怎么变得更好。」

Visual hierarchy > Decoration

Whitespace > Card

Evidence > Marketing copy

Images + diagrams > Walls of text

Questions > Feature lists

Personal > Corporate

Quiet > Impressive

Readable > Cool

# 39. Implementation Order

不要一次重构所有页面。

Step 1
建立新的 Color / Typography / Spacing Token。

Step 2
只重做：

Header
Homepage

完成后截图检查。

Step 3
重做：

Projects Index
Thoughts Index
Resources Index

截图检查。

Step 4
重做：

Credit Report Hero
Overview
Visual Slots

截图检查。

Step 5
重做：

Evolution

截图检查。

Step 6
重做：

Current System
Design Decisions
Evaluation
Failures
Current Focus

Step 7
Responsive + Accessibility。

Step 8
完整测试。

不要因为现有测试期望 DOM 结构而保留糟糕视觉结构。

如果重构导致测试需要更新，
应更新测试以验证新的正确行为。

# 40. Definition of Done — Visual

本轮只有满足以下条件才算完成：

- 首页不再存在大型 slogan
- 首页第一视觉重点为三个内容入口
- 首页不再像 SaaS Landing Page
- 大部分内容不再由 Card 包围
- Tag 数量明显减少
- 实心 Button 数量明显减少
- 授信详情不再连续出现大段文字墙
- Evolution 默认状态可快速扫读
- Case Study 已预留真实截图位置
- Current System 有真正的信息层级
- Design Decisions 可以在 10 秒内扫完
- Thoughts 看起来像文章索引，而非产品卡片
- Resources 看起来像 curated list，而非后台数据卡
- Desktop 有明显留白和阅读节奏
- 375px Mobile 不拥挤
- 页面整体更接近 editorial / personal research site
- 不使用假截图或虚构数据
- 所有原有功能测试重新通过

不要试图保守修改现有 CSS。允许大幅推翻目前的视觉结构。现有版本只保留内容、数据、路由和功能，不把现有 UI 当作需要兼容的设计基线。
